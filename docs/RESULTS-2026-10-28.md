# First physical-machine results

Date: 2026-10-28. Direct authenticated Telnet inspection of 192.168.0.133.
Only bounded inspection and isolated context probes were performed. Probe
sources and executables reside in `/tmp/pthreads-amix-261028`, created with
umask 077. No kernel, boot configuration, system library, or compiler was
replaced. Login itself updates the usual operating-system login records.

## Authoritative running baseline

`uname -a` reported, with terminal wrapping removed:

```text
UNIX_System_V amiga3000ux 4.0 2.1c 0800430 Amiga (Unlimited) 68060-261027-ia m68k
```

This identity is more relevant than dates or filenames of boot artifacts.
The user reports many installed kernel updates beyond the public baseline.
`/unix` points to `/stand/unix`; a newer `/stand/unix.z3` also exists. We have
not proven which file corresponds byte-for-byte to the running image.

## Compiler distinction

Both `cc --version` and `gcc --version` printed `2.7.2.3` in the target login.
`cc` resolves to `/usr/bin/cc`; `/usr/local/bin/gcc` points into the installed
GCC 2.7.2.3 directory. All probe results below use that native compiler at -O0.
The available GCC 14 cross-toolchain remains the planned application toolchain;
these observations do not contradict its availability.

## Header and library observations

- `/usr/include/ucontext.h` and `/usr/include/sys/ucontext.h` exist.
- pthread.h, thread.h, sys/lwp.h, and semaphore.h were not found at the exact
  `/usr/include` locations checked. Other installation locations are unexamined.
- The standard library globs checked did not identify a pthread/LWP library.
- Shared libc exports getcontext, setcontext, swapcontext, a global errno
  object, sigprocmask, sigaction, sigaltstack, sigsuspend, and poll.
- makecontext was absent from the shared-libc symbol result, but is present in
  `/usr/ccs/lib/libc.a` and was linked into the successful context-stack binary.
- The bounded shared-libc symbol search did not show clock_gettime, setitimer,
  or nanosleep. This is not proof those facilities are absent from the system.

Neither missing headers nor missing shared-libc symbols prove that the updated
kernel lacks a feature. In particular, the makecontext finding demonstrates
why link and execution tests must follow symbol inventory.

The executable's symbols showed a defined makecontext and an undefined

## Consequence and next evidence

Basic user-space context construction and switching work on this installed
kernel/libc combination with the native compiler. No module loader was needed.
This is enough to continue user-space feasibility probes, not enough to select
cooperative or preemptive scheduling, claim pthread compatibility, or establish
that blocking syscalls can be isolated between threads.

## Additional native diagnostics (not GCC 14 acceptance)

context-state.c ran through 2,000 iterations in each of two contexts at both
-O0 and -O2 with the native compiler, without -m68040. Both executions exited 0:

```text
iterations=2000,2000 state-failures=0 errno-shared=1
PASS: stack locals, d2, fp2, FPCR, signal masks across switches
Scope: cooperative switching; selected registers only
```

The two contexts held different integer/floating values, FPCR rounding modes,
and SIGUSR1 masks. errno-shared=1 confirms the need for runtime errno isolation.
This does not check every register or asynchronous signal delivery.

Native build troubleshooting: GCC 2.7 rejects modern read/write '+' asm
constraints, so matching input/output constraints were used instead (also valid
with GCC 14). The -m68040 native build emitted assembler-rejected `move.l`
instructions, so diagnostics used the native default CPU setting. No assembler,
compiler, or system-library changes were made to work around that issue.

The user explicitly requires GCC 14 cross-builds with 68060 optimizations.
Further implementation acceptance therefore uses -m68060 on that toolchain;
native diagnostics cannot substitute for it.
